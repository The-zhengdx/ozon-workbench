# 推荐给开发 Codex 的第一条任务说明

> 复制下面的内容交给负责开发本系统的 Codex。请与本包中的需求文档一起提供，不要仅发这一段提示词。

```text
你现在是本地 Ozon AI 商品加工与自动刊登系统的技术负责人和实现者。

项目根目录中的以下文件是实现依据：
- 01_项目需求规格说明书.md （权威需求）
- 02_codex_reply_v1_2.schema.json（Codex 业务回复协议）
- 03_数据库参考DDL.sql（空库参考数据模型）
- 04_接口与协议示例.md（接口示例）
- examples/（Schema 校验样例）

先完整阅读以上文件，再执行下列工作：
1. 生成按里程碑拆分的实施计划，每个里程碑说明模块、接口、数据表、测试及验收项对应关系。
2. 优先实现店铺、全局店铺上下文、完整类目树/懒加载字典、单类目单提示词、任务队列、Codex CLI Adapter、结构化 JSON 协议，再做 OSS、商品交付和刊登。
3. 本项目采用 Go + PostgreSQL + Web 管理后台 + Codex CLI `exec/resume`。本期禁止引入 MCP、Codex App Server、实时输出事件 UI、额外复杂店铺字段。
4. 严格遵守“任务 completed 后生成 N 条 products 草稿”的事务边界，不能在 Codex 报 completed 的瞬间就标记系统任务完成。
5. 所有字段的真实来源、状态机、审核边界、价格归属、任务名额和追加消息排队机制必须与需求文档一致。
6. 所有外部依赖都要设置可测试的 Mock 或 Adapter：Ozon API、OSS、Codex CLI、图像/视频生成服务。
7. 若需求文件标记为“待配置/待验证”，只实现可配置接口或阻断并报告缺少信息，禁止发明定价倍率、汇率、视频格式、官方 ID、用户凭证等。
8. 每个模块实现后执行单元测试和必要的集成测试，并报告满足了哪些 AT-XX 验收场景。数据库结构变化请提供 migration，不能直接覆盖旧表。
9. 确保应用重启后队列、Codex Session ID、消息、上传状态和刊登结果能够恢复或明确标记 uncertain；所有副作用必须幂等。
10. 实施前请先输出你发现的真实冲突或不可实现项；不要自行重新设计用户已经确认的业务范围。

第一步只输出：技术实现方案、项目目录结构、分阶段任务清单、风险及待配置项，不要一次性生成整个项目的代码。
```
