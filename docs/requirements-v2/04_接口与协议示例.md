# 附录：API / Codex CLI / 业务消息示例

> 本附录服务于 `01_项目需求规格说明书.md`；参考 URL、SKU、ID 均非真实凭证。

## Codex CLI

首次：`codex exec --json --output-schema ./02_codex_reply_v1_2.schema.json -o ./turn-001.json -C <task-workdir> "<prompt>"`

续接：`codex exec resume <SESSION_ID> --json --output-schema ./02_codex_reply_v1_2.schema.json -o ./turn-002.json "<follow-up>"`

命令参数的实际位置和支持情况以**本机** `codex exec --help` / `codex exec resume --help` 为准；调用通过 Go `exec.CommandContext` 使用参数数组，严禁拼接未经转义的 shell 字符串。

## 类目 REST（只有 curl，不使用 MCP）

- `GET /api/categories/{category_id}/types/{type_id}/attributes`
- `GET /api/categories/{category_id}/types/{type_id}/attributes/{attribute_id}/values?keyword=...`
- `GET /api/categories/{category_id}/types/{type_id}/attributes/{attribute_id}/values?page=1&page_size=100`

通过后端缓存读取；缓存未命中则由 Go 使用当前任务绑定店铺的 Ozon 凭证访问官方 API。Codex 不直接获取密钥。

## Codex 回复

固定 Schema：`02_codex_reply_v1_2.schema.json`。有效样例在 `examples/` 下。

响应外层固定 `schema_version,status,stage,message,questions,review,data,error`。状态枚举五种：`needs_input,pending_review,media_ready,completed,failed`。示例 JSON 中 `completed` **只代表 Codex 交付完成**，真正加工任务还要等待批量草稿入库事务完成。

## 交付与刊登

Codex 交付 `data.products[]` → Go 验证并构造 N 个 `api_item_json` → PostgreSQL 创建 N 个 `ozon_products(draft)` → 后续运营手动选择 SKU → `/v3/product/import` 请求 `{"items":[<api_item_json>,...]}`（每请求最多 100 个）→ 查询 `/v1/product/import/info` → 回读平台审核/可售。

不要把 `cost`、`origin_link`、`base_sku`、`generation_task_id` 写入 Ozon 导入请求中的商品对象。
